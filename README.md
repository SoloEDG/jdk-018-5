# GLYPH ASCII Studio

安装：`npm ci`

本地启动：`npm run dev`

Docker 启动：`docker compose up --build`，访问 http://localhost:18018。

## 结构描摹（03 / TRACE）

在字符密度面板下方开启「结构描摹」后，应用多出两个视图与一组约束工具：

1. **轮廓方向提取**：图像先降采样为网格亮度，再做 Sobel，得到每个单元的梯度幅值与
   8 扇区笔画方向；沿梯度做非极大值抑制得到单格宽骨架，骨架在必要时通过真实存在的
   邻格桥接成 4 连通轮廓。界面上以蓝色短线显示方向与骨架单元。
2. **引导线（原图坐标）**：在「原图描摹」视图里拖画折线，或在侧栏放置「必须连续的
   交点」。引导线与交点存的是**原图归一化坐标**，裁剪只改变视口与网格，通过裁剪预览
   可以验证线条始终钉在同一张图的位置上。交点必须在求解中被两条以上的线经过，否则
   会作为孤立交点列出。
3. **字符预算**：预算按全部单元的非空字符百分比计；硬约束（引导线、交点）优先，
   超出预算会明确报告，而不是丢掉线条假装省格子。
4. **诊断**：每条未满足的约束都带稳定编号（`G1` / `J2` / `A3` / `POLICY`）、单元编号、
   解释与可执行的放宽选项。连通性只在两个字符真的共享边时才算成立；╱╲ 只共角，
   默认计为断点，接受「允许对角线」才改变判定标准。字符面板中点击任一字符可以看到
   是哪个 `G/J/A/TONE` 决定它，以及该处对应的约束。
5. **拒绝自动边缘**：在字符面板选中自动轮廓单元，可以「拒绝此自动边缘」，该段的
   原图位置会被记录并在下一次求解中排除，随后重新列出仍未满足的约束。
6. **两种优先级对比**：同一预算、同一批约束下分别按「结构优先」「灰阶优先」求解，
   并列显示引导连通率、轮廓连通率、断点数与平均亮度偏差，以及两者字符不同的单元；
   对照画布可缩放、可悬停查看单个单元在两套策略下的字符与偏差。
7. **导出防错**：求解结果是唯一事实源。导出前会重新对即将写出的字符数组做哈希，
   与诊断携带的哈希不一致时直接拒绝导出；`诊断 JSON` 与 `.TXT` 使用同一个哈希。

### 已知的诚实边界

- 一个单元格只能放一个字符：两条线在**同一单元**交叉时，方块字符集里的 `┼` 能让
  两侧边臂都成立，但两段线自此不能各自独立追踪；若字符集无法提供足够边臂，该处会
  记为断点而不是「已连通」。
- 低密度下折线可能塌缩进一个单元，此时无法表达方向，会以「密度不足」列出，不会
  伪造成已连通。
- 裁剪区域过于狭长时网格会被钳制（最多 1200 行），钳制会作为密度约束报告出来。
